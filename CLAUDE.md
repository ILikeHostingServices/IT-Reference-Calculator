# Cross-agent project documentation

This project gets worked on across Claude Chat (planning), Claude Code (implementation), and Claude Cowork (multi-agent sessions) — work is handed off between them with no shared chat history, so this file plus `README.md` / `CHANGELOG.md` / `MEMORY.md` are the only continuity between sessions.

Keep these current as work happens, not reconstructed later:
- `CLAUDE.md` (this file) — agent-facing: conventions, gotchas, how to build/test/run. Update it whenever something surprising is learned, so the next session doesn't repeat the mistake.
- `README.md` — human-facing: what this project is, setup, usage.
- `CHANGELOG.md` — dated entries (newest first) for meaningful changes, in the spirit of Keep a Changelog.
- `MEMORY.md` (plus a `memory/` folder if it grows) — decisions, open questions, and context worth persisting across sessions, once there's real content worth capturing. Don't scaffold it empty.

If a change lands, update `CHANGELOG.md`. If a convention or gotcha is discovered, update this file. If planning for new work happened in Claude Chat before landing here, fold that context into these files as the first step rather than leaving it stranded in chat scrollback.

# Project notes

- **Release flow: staging first (ILHS website baseline, owner decision 2026-11-12).** Branch from `staging`, open the pull request into `staging`, and merge it when checks are green. The owner tests on https://calc-staging.ilhs.app (Worker `calculator-staging`, Cloudflare Access login). Only after the owner says staging testing passed, open a pull request from `staging` into `main`; merging it makes calc.ilhs.app live. Never push directly to `staging` or `main`, never force-push either, and never open a change pull request straight into `main`. Cloudflare setup and checks: `docs/DEPLOYMENT.md`. Baseline rules and the site registry: `org/baseline/WEBSITES.md` in ILHS-Internal; this site's record of exceptions: `SITE.md`; runbook and owner to-do list: `projects/it-reference-calculator/HANDOFF.md` in ILHS-Internal.

- **Stack:** vanilla HTML/CSS/JS, no build step, no npm dependencies. Scripts load in order via plain `<script>` tags and share the global `window.Calc` namespace. Logic modules in `js/*.js` (no DOM, testable in Node); page wiring in `js/ui/*.js` on top of `js/ui/core.js`; `js/app.js` must load last.
- **Run locally:** `.claude/launch.json` defines `static-server` (`python -m http.server 8931`). To run it as Cloudflare serves it (security headers, redirect, `Last-Modified`): `npx wrangler dev --var PRIMARY_HOST:127.0.0.1`.
- **Tests:** `node --test tests/*.test.js` (pass the glob; `node --test tests/` fails on Node 22). `tests/load.js` loads the logic modules into Node; add new modules to its `FILES` list. CI runs the same command (`.github/workflows/test.yml`).
- **Version:** `Calc.VERSION` in `js/version.js`. Bump it (and add a `CHANGELOG.md` entry) on every functional change; the footer shows it and `sw.js` names its cache after it.
- **Footer build time is computed at runtime**, not stamped: newest `Last-Modified` across the page's own assets via HEAD requests, formatted in America/New_York as `YYYY-MM-DD HH:MM TZ` (24 hour). Do not add a hardcoded date.
- **Footer text is fixed by the owner:** "It will not get any easier than this". Do not add a link to the repo. The feedback line (info@ilhs.app) under it was added in 2.0.0.
- **Name:** the app is "IT Reference Calculator" (`Calc.APP_NAME`); the GitHub repo is `IT-Reference-Calculator` (renamed from `calculator` on 2026-10-25, old URLs redirect). It is an ILHS site, live at https://calc.ilhs.app.
- **ILHS brand:** colors, fonts, header, and buttons copy ilhs.app (`ILikeHostingServices/ILHS-Primary-Website`, `site/assets/css/site.css`). The sizing token block in `css/style.css` must match `docs/shared/ilhs-sizing-tokens.css` exactly (`tests/site.test.js` checks). When the ILHS Shared Sizing Spec changes (in the private `ILikeHostingServices/ilhs-internal` repo, `org/brand/SIZING.md`), update both files together. ILHS is a free and open source software company, not an IT services business: do not write sales or "hire us" copy. Do not spell out ILHS. Contact address for the site is info@ilhs.app.
- **ILHS brand check (do it before publishing):** the brand guide is `org/brand/BRANDING.md` and the sizing spec `org/brand/SIZING.md` in the private `ILikeHostingServices/ilhs-internal` repo (attach it to read them); org rules are in its `org/conventions.md`. Passed on 2026-11-12. Rules that are easy to break here: only the brand palette (`--bg`, `--surface`, `--surface-2`, `--line`, `--text`, `--muted`, `--accent`, `--accent-ink`, `--accent-soft`, `--amber` for warnings, `--red` for errors; no greens or second accents); Title Case for headings, buttons, and UI labels (form labels in the HTML; result labels, box labels, and table headers go through `Calc.UI.titleCase`); every button and link at least 44 x 44 px; font sizes only from the tokens; corners 10 px cards, 8 px buttons, 6 px code and tags; no shadows; no emoji or exclamation marks; example data only on example domains, documentation IP ranges, `alex.morgan@example.com`, and "Northwind Traders". To re-check: run `tests/browser-conformance.js` (sizing checklist at all test sizes, zoom, headings, axe-core WCAG 2.2 AA) and `tests/browser-e2e.js` against `wrangler dev`; instructions are in each file's header.
- **File headers:** every first-party file starts with a header naming it, its own version, and its last edit date (ILHS convention), for example `/* js/net.js v1.0.0 (Last Rev: 2026-11-12) */`. Bump that file's version on every functional change. Vendored files and JSON are exempt.
- **Merging:** PRs merge with a merge commit (never squash or rebase), as ILHS-Owner, only when every check is green, using the full head commit SHA. Standing owner permission (ilhs-internal `org/conventions.md`): a cloud session may merge its own green PRs.
- **Adding A Tool:** (1) logic in a new or existing `js/*.js` module plus tests; (2) a `<section class="tool" id="t-ID" data-tool="ID" data-group="..." data-title="..." data-keywords="...">` in `index.html` with a `.tool-head` h2 (the menu, search, and Copy buttons are generated from it); (3) `Calc.UI.register("ID", { init })` in the right `js/ui/*.js`; (4) add any new script to `index.html` and to `ASSETS` in `sw.js` (the test fails otherwise); (5) bump the version and the changelog.
- **Share links:** every `input/select/textarea` with an id inside a tool section goes into `#tool?key=value` when it differs from its starting value (key = id minus the `ID-` prefix). Mark anything secret or bulky with `data-nostate` (passwords, Wi-Fi password, pasted headers, encoder input). Row lists made with `Calc.UI.makeList` share through the tool's `getState`/`setState`. Lookups that hit the network run from a link only through `afterSetState`, never on typing.
- **Live updates:** every tool recalculates on input/change (`Calc.UI.live`); there are no Calculate buttons except network lookups and generators. Storage / RAM: size x size arithmetic was deliberately removed; multiplication is only quantity x size.
- **Resolutions tool:** data lives in `GROUPS` in `js/resolution.js`. Ultrawide "21:9" panels reduce to 64:27, 43:18 or 12:5, and 1366x768 is 683:384; those rows carry `nominal: true`, and the lookup treats anything within `MARKETED_TOLERANCE_PCT` (3%, in `js/ui/display.js`) as a nominal match. Standard groups are at least ~6% apart, so do not raise that tolerance much. 16:10 reduces to 8:5, so compare reduced forms, never the group key string.
- **Network calls:** only `js/dns.js` talks to the internet (Cloudflare DNS over HTTPS, Google as a fallback). Any new host must be added to `connect-src` in `worker/index.js` and disclosed in the tool's `.privacy-note`.
- **Security headers / CSP** come from `worker/index.js` (no inline scripts, no `style="..."` attributes or inline `<style>`; setting `element.style.x` from JS is fine). `tests/site.test.js` rejects inline styles and handlers in `index.html`.
- **Deploy:** Cloudflare Workers Builds. Live Worker `calculator` (legacy name, kept) builds `main` with `npx wrangler deploy --env=""`; staging Worker `calculator-staging` builds `staging` with `npx wrangler deploy --env staging`. Names must match `wrangler.jsonc`, and bindings and vars must be repeated under `env.staging` (they are not inherited). Staging sets `NOINDEX` = "1", which makes the Worker send `X-Robots-Tag: noindex` and a disallow-all robots.txt; `tests/worker.test.js` covers that and the redirects. Assets directory is the repo root, so anything that must not be public goes in `.assetsignore` (docs, tests, worker, md files are already there); verify with `wrangler dev` and request the path (should 404). Wrangler's "Read N files" count includes ignored files. `run_worker_first` is on so the redirect and headers apply to every request. The sandbox proxy blocks the live domains (calc.ilhs.app, calc.syshost.app) and the DNS-over-HTTPS hosts, so test with `wrangler dev` and mock DNS in Playwright (`context.route`).
- **Gotchas found the hard way:** (a) Cloudflare redirects `/index.html` to `/`, and a redirect fails `cache.addAll`, so `sw.js` precaches `./`, never `index.html`. (b) `Calc.UI.renderData` appends; callers clear their container first. (c) When writing files with Unicode escapes like `\u2014` in a regex, check the saved file: the write can turn them into the literal characters, which then break the no-dash rule. (d) Grid children need `min-width: 0` or a wide table stretches the whole page on phones.
